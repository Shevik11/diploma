## 3. Технічне Середовище

### 3.1 Апаратні характеристики (фіксовані параметри)

- CPU: кількість ядер та частота
- RAM: обсяг та швидкість
- GPU: CUDA/NVIDIA (якщо є)
- Сховище: тип (SSD), швидкість читання/запису
- Мережа: пропускна здатність

### 3.2 Програмне забезпечення

- Docker: версія, структура Dockerfile
- VM: тип гіпервізора, операційна система
- Фреймворки для ML:
  - llama.cpp
  - vLLM
  - Ollama
  - Transformers
  - ONNX Runtime (для edge)

### 3.3 Формати моделей

- GGUF
- AWQ
- EXL2
- Квантизація: Q4/Q8, FP16 vs INT8

### 3.4 Оптимізації

- CPU Pinning
- Memory Ballooning
- Налаштування VM для ML workflow

## 4. Метрики Продуктивності

### 4.1 Метрики інференсу

- Latency: first token latency
- Throughput: tokens per second
- Response time: час повної відповіді
- QPS: кількість запитів в секунду
- Час завантаження моделі

### 4.2 Використання ресурсів

**CPU:**
- Утилізація (загальна та по ядрах)
- Context switching overhead

**RAM:**
- Використання
- Peak memory

**Диск:**
- Швидкість I/O
- Використання простору

**GPU (якщо є):**
- Утилізація
- VRAM використання

**Мережа:**
- Пропускна здатність
- Латентність

### 4.3 Операційні метрики

- Час розгортання
- Розмір образу/контейнера
- Складність конфігурації
- Час відновлення після збою
- Масштабованість (час створення кількох інстансів)

### 4.4 Стабільність та надійність

- Стабільність при навантаженнях
- Jitter (стандартне відхилення)
- Noisy Neighbour Effect

### 4.5 Енергоефективність

- Енергоспоживання (RAPL, Intel Power Gadget, scaphandre)
- CO2 еквівалент
- Екологічний вплив

### 4.6 Якість відповідей

- Точність моделі
- BLEU, ROUGE scores
- Вплив платформи на точність
- Мультимовність моделей

## 5. Методологія Тестування

### 5.1 Типи тестів

- Cold start test: запуск з нуля
- Warm test: запуск після прогріву
- Послідовні запити: один за одним
- Конкурентні запити: паралельні навантаження
- Стрес-тести: граничні навантаження

### 5.2 Сценарії тестування

- Симуляція чат-бота з рандомними промптами
- Датасети: Alpaca, Lotus
- Real-world use cases

### 5.3 Сценарії відмов

- Out of Memory
- Model crash
- Host overload
- Container restart vs VM reboot
- Recovery time
